## Executive verdict

RevenueOS has a credible, differentiated Core architecture and a compelling part of
the product experience. It is unusually strong at deliberate face-to-face and
no-recording capture, provenance, source classification, contradiction preservation,
reviewable methodology, longitudinal memory and a calm personal Daily. Those are
material advantages, not substitutes for missing commodity capability.

Core is **not yet strong enough to begin Prospect**. Building a new research surface
before users can safely use Core with real customer data, retrieve the knowledge
already captured and apply an approved CRM update would add breadth before proving
the central Evidence → Brain → Action loop. It would also add another destination to
an already crowded shell.

Insert these work orders before WO-026:

1. **WO-025A — Core Experience & Design-Partner Readiness**: satisfy the target-
   environment customer-data, privacy, provider and operational gates; support one
   complete existing capture-to-review path; consolidate Core navigation and replace
   technical onboarding with an outcome-led first-interaction journey.
2. **WO-025B — Ask RevenueOS**: deliver permission-scoped, evidence-cited universal
   search and Q&A across authorised account, Opportunity and portfolio context.
3. **WO-025C — Core CRM Sync**: select Salesforce or HubSpot from design-partner
   evidence and deliver one production read/match plus reviewed-write path using the
   existing Action/Execution safety contract.

Then repeat the behavioural Checkpoint 1 gate. Proceed to WO-026 only when real users
can navigate Core unaided, reach useful reviewed intelligence after a real first
interaction and complete an approved CRM update through the selected connector.

## Capability findings

### A. Capture

| Path                                       | Assessment            | Reason                                                                                                                                                    |
| ------------------------------------------ | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Face-to-face                               | **Strong**            | Companion, explicit passive/record modes, markers, Visual Evidence and immediate Debrief make non-desk work first-class.                                  |
| Browser recording                          | **Sufficient**        | Resumable private upload, bounded media, worker and retention contracts exist; foreground/browser and default-off production limits are honest.           |
| Online meetings                            | **Needs improvement** | Platform navigation and deliberate transcript/recording import work, but no native join, fetch or automatic ingest exists.                                |
| Phone calls                                | **Sufficient**        | Direction/outcome, Contact association, preparation, debrief and authorised recording import cover the manual workflow without false interception claims. |
| Presentations/workshops/site visits/events | **Needs improvement** | Interaction types, preparation, Companion and visual/debrief paths exist, but the journeys need real-user validation and remain browser-led.              |
| Unrecorded interactions                    | **Strong**            | Voice Journal, typed notes and adaptive Debrief are legitimate sources rather than degraded recording fallbacks.                                          |
| Visual Evidence                            | **Strong**            | Ownership, source type and review are explicit; no face recognition or automatic Contact promotion exists.                                                |
| Imported recordings/transcripts            | **Sufficient**        | Authorised recording reuse and bounded TXT/VTT/SRT import produce versioned source-neutral transcript evidence.                                           |

The minimum pre-Prospect requirement is not a meeting bot. It is one complete,
production-approved capture-to-review route for the chosen cohort, with measured
time, failure and correction behaviour. Automatic online capture remains a
high-value later Core integration unless design-partner usage proves it necessary to
make that first route viable.

### B. Transcription and Evidence

The architecture is strong: immutable transcript versions and segments, neutral
speaker labels, provider abstraction, explicit partial/failure states, tenant-scoped
private storage, short raw-audio retention, export/deletion lineage, source
classification and review are implemented. RevenueOS also avoids treating a speaker
label or seller report as customer-confirmed truth.

The product-readiness gap is operational. The deterministic provider is the normal
path; the OpenAI transcription adapter is optional; production customer-content use
remains prohibited pending target-environment, provider, privacy and operational
approval. WO-025A must turn one already-designed path into supported design-partner
behaviour and publish its limitations. That is **A — MUST CLOSE BEFORE PROSPECT**.

### C. Conversation structuring

RevenueOS sufficiently covers summaries, buying signals, objections, competitors,
stakeholders, decisions, action items, risks, open questions, follow-up and next best
action in strict schemas. Commitments and customer requests are represented across
actions, decisions, questions and Evidence rather than as a single explicit
portfolio projection. Timeline change is supported by deterministic Revenue Brain
comparisons.

The gap is not another extractor. It is a concise source-neutral deal narrative that
reconciles all final sources and makes commitments/customer requests easy to find.
That can follow Prospect inside the WO-035 Workspace/Pipeline work. Existing typed
structuring is **C — SUFFICIENTLY COVERED**; a separate unbounded “AI notes” feature
would be **E — DO NOT BUILD**.

### D. CRM administration and sales-admin promise

**No. RevenueOS cannot credibly promise “Finish the meeting and RevenueOS handles the
sales admin” today.** It can prepare source-aware intelligence, a follow-up draft and
reviewable Action proposals. It can record approval, build a server preview and
simulate email, calendar, CRM and task outcomes. It cannot authenticate to, read,
match, update or reconcile a production Salesforce/HubSpot account, and it cannot
send the approved follow-up.

Exact missing pieces are:

- supported automatic or one-step finalisation from the chosen production capture
  path into current final intelligence;
- design-partner-approved external processing and evaluated output quality;
- automatic, current Action and methodology proposal preparation after final review;
- provider account installation, OAuth/credential lifecycle and least scopes;
- tenant-scoped CRM identity matching, field mapping and source-authority policy;
- a real adapter for the approved field/activity/task change;
- provider idempotency, conflict handling, receipts, uncertain-outcome reconciliation,
  revoke/disconnect and operator recovery; and
- a selected mail adapter before the broader claim includes sending follow-up.

Move **one** design-partner-selected CRM connector forward as WO-025C. Preserve
review-by-default and exact confirmation: automatic preparation is the commodity
need; silent mutation is not. Keep the second CRM, broader bidirectional sync and
connector matrix in WO-042. Keep real mail/calendar execution with the selected
WO-040 or WO-041 ecosystem. Until then the honest message is “RevenueOS prepares the
admin for your review,” not “handles the admin.”

### E. Sales Methodology

WO-024 meets the important Core need: four standard methods plus bounded custom
definitions; current Evidence auto-projection; five explicit trust states; source,
freshness and conflict explanation; gap questions; history; and review/correction.
It feeds preparation and Actions without becoming a competing fact store.

SPIN, Challenger, Sandler, GAP Selling and Solution Selling remain configuration
possibilities, not implemented standards. More named methods are not a readiness
gate. Manager roll-up belongs in WO-039.

The lack of a primary numeric methodology score is **D — DIFFERENT / BETTER
APPROACH**, not a disadvantage. Counts can aid scanning, but a percentage conflates
unknown, stale and conflicting evidence and invites stage gaming. RevenueOS should
compete on explainable gaps and supported next questions.

### F. Deal Intelligence

RevenueOS currently gives a seller a **richer evidentiary understanding than a
traditional CRM** when the source set is populated: latest validated intelligence,
longitudinal change, risks, stakeholders, contradictions, methodology gaps and next
action are inspectable. It does not yet give the faster overall deal answer of a
mature revenue-intelligence product because data capture is manual, cross-source
state is fragmented across panels and universal Q&A is absent.

Treat the underlying intelligence as **C — SUFFICIENTLY COVERED**. Treat the concise
portfolio/deal projection and Workspace simplification as **B — CORE ROADMAP — CAN
FOLLOW PROSPECT**, owned by WO-035. Ask RevenueOS is the pre-Prospect retrieval gap.

### G. Forecasting

Forecasting **can remain WO-038**. It is competitively important but should not move
before Prospect because it depends on stable lifecycle events, pipeline management,
metric definitions, targets and sufficient representative outcomes. Moving it now
would reward false precision.

The minimum lovable Core forecast remains:

- pipeline amount by period, scope and currency;
- central estimate and defensible range;
- deal-level explanation with source-linked factors;
- historical conversion and cycle distributions only for sufficient cohorts;
- methodology, stakeholder, commitment, inactivity and Evidence context;
- versions, freshness, calibration and eventual outcome;
- distinct seller, manager and system views with preserved overrides; and
- an explicit unavailable/rules-only state when evidence is sparse.

Classification: **B — CORE ROADMAP — CAN FOLLOW PROSPECT**.

### H. Coaching

Current briefs, gap questions, debriefs, Actions and Next Best Action provide
opportunity guidance, but there is no coaching history, outcome association,
practice loop or manager workflow. Future coaching should be opportunity-specific,
methodology-aware, historical-pattern-aware and linked to observed outcomes with
uncertainty. It should suggest the next behaviour and cite representative examples.

Reject talk-time targets presented as performance, call-score theatre, emotion or
personality inference, simplistic rep scores, employee ranking and covert monitoring.
Keep coaching with WO-039 after analytics/forecast foundations; allow Ask to answer
evidence-grounded deal-strategy questions without calling that a performance score.

Classification: **B — CORE ROADMAP — CAN FOLLOW PROSPECT**.

### I. Manager Intelligence

There is no current manager product. Both current roles receive a personal Daily;
admin surfaces are operational. WO-039 remains correctly timed after Pipeline,
Analytics, Targets and Forecast because managers need reliable team scope and
reconciled definitions before seeing roll-ups.

WO-039 should answer: where the team needs help, which deals are at risk, which gaps
and commitments matter, whether pipeline is sufficient, which forecast is credible
and where intervention can change an outcome. It must not rank employees.

Classification: **B — CORE ROADMAP — CAN FOLLOW PROSPECT**.

### J. Ask RevenueOS

Ask RevenueOS is **Core** and should precede Prospect as WO-025B. The current
Assistant is a placeholder while Daily exposes a “Search” CTA that opens it. Adding
more Prospect information before making existing relationship knowledge retrievable
would deepen product fragmentation.

The capability is universal Search with an evidence-backed answer mode, not a generic
chat product. It needs:

- normal navigation and exact/filtered structured search before model synthesis;
- permission- and tenant-scoped account, Opportunity, Interaction, Action,
  methodology and portfolio query plans;
- final, current, authorised source selection only;
- citations and deep links for every material claim;
- explicit unknown, conflicting, stale and incomplete answers;
- bounded result sets and no hidden transcript/body expansion;
- metadata-only telemetry and prompt/provider controls; and
- no tool authority or external action from an answer.

Place Search as a utility available from Home and contextual workspaces. Do not add
another top-level “Assistant” destination once the migration is complete.

Classification: **A — MUST CLOSE BEFORE PROSPECT**.

### K. Win/Loss Intelligence

Win/Loss Intelligence is **Core**, not an add-on. Add **WO-036B — Win/Loss
Intelligence** immediately after Sales Analytics and before Targets/Forecast. It
depends on explicit won/lost lifecycle events, outcome review and reproducible cohort
definitions, so it should not move before Prospect.

The MVP should first create a reviewed deal-level explanation from interactions,
objections, competitors, methodology, stakeholders, pricing evidence, documents,
emails, commitments, actions and Revenue Brain history. Aggregate themes should
appear only for sufficient cohorts, retain source/outcome links and use association,
not causal language. The seller/manager may correct the outcome explanation without
rewriting source Evidence.

Classification: **B — CORE ROADMAP — CAN FOLLOW PROSPECT**.

### M. RevenueOS Daily

WO-025 passes its intended gate. A first-time seller can identify the primary action
quickly; the dark priority card has one CTA; Home composes Interactions, Actions,
deal attention, descriptive pipeline and existing recommendations without another
score or chart wall. It is more useful than a generic CRM dashboard because reasons
are actionable and linked to evidence-bearing work. Mobile correctly leads with the
next Interaction and reduces analytic detail.

The surrounding mobile shell weakens that success: the horizontal eleven-item
navigation is clipped and makes the product feel larger than Daily. Search also leads
to a placeholder. Daily itself is **C — SUFFICIENTLY COVERED**; shell/Search repair is
owned by WO-025A/B.

### N. Workspace and Deal Rooms

The current Opportunity Workspace has the right ingredients but not yet the final
“organised evidence and working memory” experience. It places methodology,
association, customer Evidence, Actions, Revenue Brain, reported/visual intelligence,
ten Meeting Intelligence panels and recent Meetings in one long sequence. Account
context is less cohesive, and ordinary source/files navigation is incomplete.

Do **not** move the file-heavy Deal Room from WO-043. It depends on secure storage,
search and WO-032 Create assets. Instead, WO-025A should simplify summary/order and
WO-035 should complete the ordinary Opportunity sections and source-neutral deal
projection. Keep WO-043 for governed assets and extended collaboration.

Classification: ordinary Workspace refinement is **B**; full Deal Room remains **B**
at WO-043.

### O. UX and simplicity

The formal findings are in the
[Core simplicity readiness review](../02-design/core-simplicity-readiness-review.md).
The central finding is that Daily is obvious, individual capture/review flows are
understandable, but the shell, onboarding and stacked Opportunity experience expose
the implementation taxonomy. Prospect must not be added to that structure.

WO-025A should establish the Core-only shell as Home, Sell, Pipeline and Insights,
with Search and Settings as utilities; preserve legacy URLs; group Companies,
Contacts, Opportunities, Interactions, Meetings and Tasks inside the user questions
they serve; and use summary → why → evidence disclosure on Opportunity. Mobile should
be Today, Interactions, Actions and Search.

Classification: **A — MUST CLOSE BEFORE PROSPECT**.

### P. Onboarding and time to value

Current onboarding is safe but technical: it asks a user to create entities, paste a
transcript, generate Meeting Intelligence and open named architecture surfaces. It
does not start from the seller's desired outcome, import their current opportunity or
make the first Daily obviously useful. Existing CRM users would duplicate data.

Targets for WO-025A/C:

- an invited seller understands the Home promise and next step within five minutes;
- an administrator can connect and validate the selected CRM path in one assisted
  session, with scope and mapping visible;
- a seller does not re-key an existing Company, Contact or Opportunity;
- meaningful Sales Brain value appears during or within ten minutes of the first
  supported real Interaction ending; and
- the seller can review intelligence, approve one useful action and see the CRM
  receipt without learning internal component names.

These are product targets to validate, not current performance claims.

Classification: **A — MUST CLOSE BEFORE PROSPECT**.

### Q. Security and trust

The repository is strong on explicit tenant predicates, forced RLS, source lineage,
strict outputs, correction/review, deliberate consent, retention, deletion, export,
safe logs, exact Action approval, idempotency and simulation labelling. The security
architecture is ahead of the minimum feature benchmark.

Real design-partner blockers remain: production customer data is explicitly
prohibited; the target identity/organisation policy, provider processing terms and
regions, secrets, private storage, monitoring, backup/restore, incident response and
external assessment are operational dependencies; and no live connection has passed
provider-specific OAuth, scopes, webhook, revoke, deletion and reconciliation gates.

WO-025A must close or explicitly evidence these release gates for the offered cohort.
WO-025C must perform the connector-specific review. Security controls are otherwise
**C — SUFFICIENTLY COVERED**; launch approval is **A — MUST CLOSE BEFORE PROSPECT**.

### R. Positioning

Credible today, with the current private/synthetic boundary stated:

- “See what matters today and what to do next.”
- “Prepare for customer conversations from source-aware relationship memory.”
- “Capture useful context even when recording is not appropriate.”
- “Review the evidence behind methodology gaps and next actions.”

Not credible today:

- “Never write meeting notes again.”
- “Finish the meeting. RevenueOS handles the admin.”
- “Your CRM updates itself.”
- “Forecast with confidence.”
- “Coach every rep from every call.”
- “Ask anything about your revenue.”

After WO-025A/B/C the honest near-term proposition is: **“Finish the meeting.
RevenueOS prepares the follow-through, shows its evidence and applies the CRM update
you approve.”** The broader “handles the admin” claim requires a live mail path and
measured reliability as well.

Each finding has exactly one checkpoint class.

### A — MUST CLOSE BEFORE PROSPECT

  WO-025A;
- evidence-backed universal Search/Ask — WO-025B; and
- one design-partner-selected CRM read/match and approved-write connector — WO-025C.

### B — CORE ROADMAP — CAN FOLLOW PROSPECT

- selected online-meeting/productivity connector and real mail/calendar execution —
  WO-040 or WO-041;
- source-neutral Pipeline/Opportunity projection and ordinary Workspace refinement —
  WO-035;
- Sales Analytics — WO-036;
- Win/Loss Intelligence — new WO-036B;
- Targets/KPI — WO-037;
- explainable calibrated forecasting — WO-038;
- coaching and Manager Intelligence — WO-039;
- broader CRM connector coverage and bidirectional sync — revised WO-042; and
- governed file-heavy Deal Rooms — WO-043.

### C — SUFFICIENTLY COVERED

- deliberate face-to-face and no-recording capture portfolio;
- versioned transcript/Evidence lineage, source classification and contradiction
  handling;
- structured summaries, signals, objections, competitors, stakeholders, decisions,
  actions, risks, questions, follow-up and next action;
- personal Daily composition and prioritisation;
- reviewable Action proposal/approval lifecycle and execution safety foundation;
- MEDDIC, MEDDPICC, BANT, SPICED and bounded custom methodology; and
- tenant isolation, retention/export/deletion and safe-log architecture, subject to
  the separate target-environment launch gate.

### D — DIFFERENT / BETTER APPROACH

- categorical methodology Evidence states instead of a primary completion score;
- review-by-default external changes instead of silent autonomous CRM mutation;
- no-recording Debrief/Voice Journal as a first-class path rather than mandatory
  recording;
- source-specific documents, email and Visual Evidence rather than treating every
  input as equivalent conversation truth;
- longitudinal immutable memory and contradictions instead of last-write-wins
  summaries; and
- optional native CRM as an add-on while external systems can remain authoritative.

### E — DO NOT BUILD

- employee ranking, simplistic rep scores and surveillance telemetry;
- emotion, personality, deception or protected-trait inference;
- opaque close probability or methodology-score theatre without calibration and
  explanation;
- unbounded autonomous sends, CRM writes or self-approving agents;
- a generic chatbot or a chat destination on every page;
- mandatory/covert meeting bots and unsupported ambient capture;
- a feature-per-navigation-item shell, chart wall or vanity activity dashboard; and
- a Salesforce clone, arbitrary workflow/code engine or universal connector matrix.

## Core and add-on boundary decision

Confirm the existing Core definition: Sales Brain, Sales Methodology, RevenueOS
Intelligence, RevenueOS Workspace and RevenueOS Daily. Clarify that the following are
Core capabilities or enabling infrastructure: Ask RevenueOS, Win/Loss Intelligence,
forecasting, coaching, Manager Intelligence and enough production CRM integration to

connector is not the native CRM add-on; it is how Core honours the customer's chosen
system of record. Large connector breadth, advanced governance and unusually costly
integration features may be packaged commercially only after a complete Core loop is
available.
